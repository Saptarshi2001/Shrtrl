Shrtrl v1 analytics: queryability report

Repository snapshot: 4 October 2026. Method: static inspection of the current workspace; no code or tests changed. Meaning of “queryable”: an end user can request an analytics result through a working v1 HTTP endpoint. On that definition, no click analytics are currently queryable through v1. The controller declares routes, but its methods do not return responses, call a service overload that does not exist, and use SQL that does not match the table. The redirect path does not publish an event. AnalyticsController.java:20–102, AnalyticsService.java:54–58, UrlController.java:70–88

This report treats the code as it is, including work in progress in the checkout. It does not treat the older analytics-module-review.md as implementation evidence.

Data available for future queries

The ClickHouse events table contains event_id UUID, userid UUID, shortcode LowCardinality(String), occurred_at DateTime64(3, 'UTC'), country, state, ip, user_agent, and referrer. The latter five are strings and default to empty. It is a MergeTree partitioned weekly (toMonday(occurred_at)) and ordered by (userid, shortcode, occurred_at, event_id). No clicks, date, timestamp, countries, states, urlid, destination URL, group ID, device class, browser, bot flag, or conversion field exists. 001_create_events.sql:1–15

The Java Event has matching logical fields and maps to a PostgreSQL analytics_outbox table; the outbox is an ingestion queue, not the dashboard query source. Event.java:12–42, V2__create_analytics_outbox.sql:1–15, AnalyticsService.java:26–40

The URL database separately holds urlid, longurl, shortcode, created_date, and owning userid; group membership is in group_url. This supports URL inventory and could supply labels or group filters after deliberate cross-store query design. The ClickHouse events table itself has no group or destination key. Urls.java:28–53, V3__create_group_url.sql:1–13

What the existing columns can support, once collection and API querying work

Question Possible measure / grouping Caveat
How many clicks? count() by owner and time range; by shortcode Count is event rows, subject to missing producer events and possible replay duplicates.
Which links lead? GROUP BY shortcode, rank by count No title/destination in ClickHouse; join or enrich from URL database.
When do clicks happen? Hour/day/week/month buckets from occurred_at; recent minute Stored timestamp is UTC. Define user timezone and exclusive end boundary in API.
Where are clicks from? GROUP BY country, state, or both Fields may be empty; code shows no geolocation enrichment. State names can collide across countries.
Who referred traffic? GROUP BY referrer; parse host for domains Raw referrer can be empty or contain sensitive query strings. Domain rollup is derived, not stored.
Which clients clicked? Group raw user_agent; derive browser/device/OS later No parsed device, browser, or bot dimensions exist.
How many apparent unique visitors? uniqExact(ip) or approximate unique IPs IP is not a reliable person identifier; NAT, proxies, changing IPs, and privacy limits apply. No visitor/session ID exists.
Which events occurred? Raw event list with time and dimensions Sensitive fields require access control, pagination, and retention rules.

Each item in this table is a schema-supported query idea, not an implemented HTTP endpoint. The raw event fields are enough for those calculations if events arrive; the current redirect path does not send them. UrlController.java:70–88

Illustrative direct ClickHouse SQL

These examples are operator-level SQL sketches, not v1 API requests or verified executions. Replace the example UUID and UTC instants. Always scope by the authenticated owner in an application implementation. The half-open range [from, to) avoids double counting at adjacent boundaries.

-- Owner summary for a UTC time range
SELECT count() AS clicks, uniqExact(shortcode) AS clicked_links
FROM events
WHERE userid = toUUID('11111111-1111-1111-1111-111111111111')
  AND occurred_at >= toDateTime64('2026-10-01 00:00:00', 3, 'UTC')
  AND occurred_at <  toDateTime64('2026-10-02 00:00:00', 3, 'UTC');

-- Daily trend, including only days with rows
SELECT toDate(occurred_at, 'UTC') AS day, count() AS clicks
FROM events
WHERE userid = toUUID('11111111-1111-1111-1111-111111111111')
  AND occurred_at >= toDateTime64('2026-10-01 00:00:00', 3, 'UTC')
  AND occurred_at <  toDateTime64('2026-11-01 00:00:00', 3, 'UTC')
GROUP BY day ORDER BY day;

-- Top links for the same owner (add the desired time predicate)
SELECT shortcode, count() AS clicks
FROM events
WHERE userid = toUUID('11111111-1111-1111-1111-111111111111')
GROUP BY shortcode ORDER BY clicks DESC, shortcode ASC LIMIT 20;

-- Country / state breakdown, keeping state paired with country
SELECT country, state, count() AS clicks
FROM events
WHERE userid = toUUID('11111111-1111-1111-1111-111111111111')
GROUP BY country, state ORDER BY clicks DESC LIMIT 20;

-- Last minute, sorted for a stable raw-event view
SELECT event_id, shortcode, occurred_at, country, state, referrer
FROM events
WHERE userid = toUUID('11111111-1111-1111-1111-111111111111')
  AND occurred_at >= now64(3) - INTERVAL 1 MINUTE
ORDER BY occurred_at DESC, event_id DESC LIMIT 20;

The schema supports similar groupings for referrer and user_agent, and uniqExact(ip) for unique IP counts. An application should pass typed/bound values through the service's parameter map rather than interpolate user input. AnalyticsService.java:54–58

Key limits and gaps for v1 planning

  1. No click producer: EventStorage is injected into UrlController, but its only call in the redirect method is commented out. Cache entries hold only the long URL, so a cache hit also lacks the owner ID needed for an event. UrlController.java:38–45, UrlController.java:70–84, UrlCacheService.java
  2. No analytics HTTP contract: No successful ResponseEntity body, DTO, validation, size cap, stable pagination, or documented timezone behavior is implemented. page is never used. AnalyticsController.java:30–102
  3. Authorization risk: Every future query must bind the session's USER_ID; the live SQL currently spans all users. AuthController.java:109–114, AnalyticsController.java:30–42
  4. Data quality: The transport workers send batches to ClickHouse, but current MergeTree has no event-ID deduplication guarantee. Retried deliveries can inflate counts; empty geo/referrer/client fields also produce unattributed buckets. RedisWorker.java:63–76, OutboxWorker.java:37–48, 001_create_events.sql:7–15
  5. Unsupported metrics: Unique people, sessions, conversions, destination performance after edits, bot-filtered clicks, campaign attribution, and group analytics cannot be stated as native event measures from this schema. They need definitions, extra collection or joins, and in some cases new fields. 001_create_events.sql:1–15, Urls.java:28–53

Practical v1 query surface to implement

The smallest coherent API would expose an owner-scoped summary, a time series, a per-link ranking, country/state breakdowns, referrer breakdown, and recent events, all with a defined UTC or account-timezone window and bounded results. This is a recommendation inferred from available columns, not a statement that these endpoints exist. It requires a working producer, corrected controller/service calls and SQL, response DTOs, owner filtering, and clear handling of late or duplicate events. The current query primitive can execute SQL with a parameter map after those pieces are connected. AnalyticsService.java:54–58
