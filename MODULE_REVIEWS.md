# Module Reviews

This file contains only findings that remain open after the users and groups
authorization, validation, conflict-handling, and API-test corrections.
Priorities mean: **P0** = security/correctness issue to fix before exposing the
API, **P1** = important reliability or contract issue, and **P2** =
maintainability/test coverage improvement.

## Users Module Review

### P1

1. **Update DTO validation is incomplete and duplicated in the controller.**
   `UserRequest` has no Jakarta validation constraints, while `UserController`
   manually rejects only null or blank values. It does not enforce the
   database's 30-character username maximum or validate email syntax/length.
   Add `@NotBlank`, `@Size(max = 30)`, and `@Email` as appropriate, then use
   `@Valid` on the request body.

2. **Password policy is not enforced.** `ChangePasswordRequest` permits
   arbitrarily short or long plaintext passwords. Add validation constraints
   for the chosen password policy and use `@Valid`; the plaintext limit is
   separate from the 60-character BCrypt hash column.

### P2

1. **`UsersService` exposes broad CRUD methods that are not authorization-aware.**
   Methods such as `save`, `getUsers`, `deletebyId`, and `findById` make it easy
   for a future caller to bypass use-case boundaries. Keep only the operations
   needed by authentication and self-service account workflows unless an
   explicit administrator API exists.

2. **Naming and dead code reduce clarity.** Examples include `userservice`,
   `containerusr`, a capitalized local variable named `Users`, unused
   `HttpStatus` locals, obsolete comments, and inconsistent formatting.

3. **Users persistence coverage remains incomplete.** The users controller and
   real security-chain authorization regression tests are now current, but
   PostgreSQL Testcontainer coverage is still needed for username/email
   conflicts, password changes, account deletion/cascade behavior, and complete
   Flyway/entity alignment.

### Persistence/schema alignment that is currently correct

- UUID IDs generated by Hibernate fit PostgreSQL's `UUID` primary key.
- Username length and uniqueness align at 30 characters.
- Email uniqueness aligns; an explicit DTO/entity maximum would clarify the
  public contract.
- BCrypt's 60-character encoded value aligns with the password column.

## Groups Module Review

### P1

1. **The URL-to-group domain relationship is missing.** Groups belong to users
   and URLs belong to users, but URLs have no `groupid` foreign key or join
   table. Decide whether a URL belongs to zero/one group or many groups, then
   add the corresponding migration, entity mapping, owner-safe add/remove
   operations, and indexes. Both the URL and group must have the same owner.
